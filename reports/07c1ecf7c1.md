NOTE|Cookie written by client JS lacks HttpOnly and relies only on secure flag; set via `document.cookie` with `domain=fyers.in`, `max-age` derived from local clock so expiry varies by user timezone
NOTE|Notification "Read More" link href is populated from external JSON (`link.href = item.url`) and rendered with `target="_blank"` but no `rel="noopener noreferrer"`, enabling tabnabbing if JSON is compromised
NOTE|notificationHTML() contains malformed template fragments (`src=+"-icon.svg"`, `` src=`+`${ASSETS_PATH}images/right-arrow.svg`+` ``) yielding invalid markup at runtime
NOTE|callNotificationsOnInterval() calls `resolve()` inside setInterval; subsequent calls are no-ops and the interval handle is never cleared after first resolution
NOTE|Notification body/title are injected via innerText (XSS-safe), but banner HTML is prepended to <body> with innerHTML from static template only
NOTE|COOKIE_NAME embeds `getUserID()` parsed from any cookie containing "_userID" without sanitization; a malicious cookie value with `=` or `,` could corrupt the notification-id cookie
NOTE|filterNotifications() assumes `data[currentDateKey]` exists when visitedIds is empty; if key lookup fails, unhandled TypeError can break the fetch promise chain
NOTE|ASSETS_PATH/image content and JSON are served over HTTPS only (no SRI/hash pinning for remote scripts/images)
